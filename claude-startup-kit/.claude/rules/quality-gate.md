# 代码质量门禁

## 你完成任何代码变更后，必须自查以下条目：

### 1. 风格一致性
- [ ] 代码风格与项目已有文件一致（见 CLAUDE.md「代码规范」）
- [ ] 命名规范与周围代码统一（变量/函数/文件）
- [ ] API 返回格式统一 `{ code: 0, data: ... }` / `{ code: 非0, msg: '...' }`
- [ ] 缩进、引号、分号风格与已有代码一致

### 2. 边界处理
- [ ] 所有 ID 参数已做类型转换（`parseInt` / 类型校验）
- [ ] 所有数组操作前检查非空
- [ ] 所有外部 API 调用有 `try-catch`
- [ ] 所有数据库写操作有错误处理
- [ ] 分页参数有默认值

### 3. 安全
- [ ] 用户输入已做校验和清洗
- [ ] 需要认证的接口已加认证中间件
- [ ] 不硬编码密钥、密码、Token
- [ ] 返回前端的用户数据已脱敏（手机号/密码/Token）

### 4. 不破坏已有功能
- [ ] 不修改已有函数签名（参数和返回值）
- [ ] 如需改函数签名，先搜索所有调用位置
- [ ] 不改已有路由的 URL 路径
- [ ] 新增字段使用可选（不影响已有数据）

### 5. 不引入新依赖
- [ ] 优先使用项目已有依赖或原生实现
- [ ] 如确需新依赖，先更新 CLAUDE.md 说明原因

### 6. 不重复造轮子
- [ ] 先检查 CLAUDE.md「已知工具函数」清单
- [ ] 先搜索项目中是否已有类似实现

### 7. 自验证
- [ ] 后端接口改动：已用 curl 或类似方式测试
- [ ] 前端页面改动：列出所有受影响页面
- [ ] 数据模型改动：检查已有数据兼容性

## 违规后果

自查不通过 → **先修再 commit**，不带着已知问题提交。
