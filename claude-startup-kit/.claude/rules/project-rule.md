# 项目协作规则

## 核心约束

1. **每次开始工作前**：git pull + 完整阅读 CLAUDE.md
2. **做完任何代码变更后**：git add + git commit + git push
3. **如果做出架构决策**：必须更新 CLAUDE.md 相应段落
4. **如果发现 CLAUDE.md 信息过时**：直接修正它

## 代码风格

- 保持和已有代码风格一致，不要引入新范式
- 项目具体规范见 CLAUDE.md「代码规范」节

## 提交信息格式

```
<类型>: <简短描述>

类型选项：feat(新功能) / fix(修bug) / refactor(重构) / docs(文档) / style(UI) / perf(性能)
```

## 与其他 Claude 实例协作

- 你可能是多个 Claude 实例中的一个
- 修改文件前检查是否有人在改同一个文件（看 git log）
- 如遇冲突，保留两边的改动，不要暴力覆盖
- CLAUDE.md 是唯一的共享上下文，依赖它来理解项目
