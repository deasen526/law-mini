# 任务提示词模板

## 使用方式

你不是技术背景。给 Claude 下任务时，从下面选一个模板，填入方括号内容。

---

## 模板A：加新功能

```
任务：在 [哪个模块/页面] 加一个 [功能描述]

要求：
1. 参考已有代码风格，不要引入新范式
2. 改完后用 curl 测试一次（如果是后端）
3. 列出所有被修改的文件
4. 提交时用格式：feat: [简短描述]

验收标准：[一句话描述什么算完成]
```

---

## 模板B：修 Bug

```
任务：修 Bug — [Bug 现象描述]

要求：
1. 先定位根因，不要猜
2. 修完后验证：之前 [Bug现象] → 现在 [预期行为]
3. 确保修复不引入新问题

验收标准：[Bug现象] 不再出现
```

---

## 模板C：代码审查

```
任务：Review [某个目录/某次提交/某个 PR]

要求：
1. 只找问题，不改代码
2. 问题分三级：
   - 🔴 致命（会导致崩溃/安全漏洞）
   - 🟡 重要（边界情况未处理/性能问题）
   - 🟢 建议（风格不一致/可优化）
3. 每个问题标注具体文件和行号
```

---

## 模板D：加新页面

```
任务：在 miniprogram/pages/ 下新建 [页面名] 页面

要求：
1. 参考 pages/product-detail/detail.vue 的代码结构
2. 在 pages.json 注册新页面路径
3. 页面数据从后端 API 获取（新接口也一并写）

验收标准：用户能 [具体操作] 看到 [具体结果]
```

---

## 模板E：调试/排查

```
任务：排查问题 — [描述异常现象]

要求：
1. 先读相关代码，不急着改
2. 检查最近的 git log 看是否由某次提交引入
3. 找到根因后，先向我确认再修改
```

---

## 模板F：日常维护

```
任务：git pull → 读 CLAUDE.md → 检查服务器状态 → 修复任何异常

如果服务器挂了：[restart 命令]
如果代码有冲突：[报告冲突文件]
如果一切正常：[报告运行状态]
```
