# 代码质量门禁

## 你完成任何代码变更后，必须自查以下条目：

### 1. 风格一致性
- [ ] 后端所有文件使用 `require/module.exports`（不允许 ES Module `import/export`）
- [ ] 小程序所有 `.vue` 文件使用 `<script setup>` 语法
- [ ] API 返回格式统一：`{ code: 0, data: ... }` 成功 / `{ code: 非0, msg: '...' }` 失败
- [ ] 金额统一用 **分**（整数），前端显示时 `/100`
- [ ] 缩进、引号风格与周围代码一致

### 2. 边界处理
- [ ] 所有 `req.params.id` 用 `parseInt()` 转换
- [ ] 所有数组操作前检查 `length > 0`
- [ ] 所有外部 API 调用有 `try-catch`
- [ ] 所有数据库写操作有错误处理
- [ ] 分页参数有默认值（page=1, pageSize=10）

### 3. 安全
- [ ] 用户输入不能直接拼到 JSON key 里
- [ ] 管理后台接口都有 `adminAuth` 中间件
- [ ] 不硬编码密钥、密码（始终用 `config.xxx` 或 `process.env`）
- [ ] 返回给前端的用户数据不暴露 `openid`

### 4. 不破坏已有功能
- [ ] 不修改已有函数的签名（参数和返回值）
- [ ] 如需改函数签名，先搜索所有调用位置
- [ ] 不改已有路由的 URL 路径
- [ ] 新增字段用可选（不影响已有数据）

### 5. 不引入新依赖
- [ ] **禁止** `npm install` 任何新包（项目原则：零依赖）
- [ ] 如果需要日期格式化，用原生 `new Date()` 方法
- [ ] 如果需要唯一ID，用 `Math.random() + Date.now()`

### 6. 不重复造轮子
- [ ] 已有工具函数（见 CLAUDE.md 底部）
- [ ] `server/utils/orderNo.js` — 生成订单号
- [ ] `models/store.js` — 数据库所有操作（CRUD/sum/count）
- [ ] `api/index.js` — 小程序端所有 API 请求封装

### 7. 自验证
- [ ] 改后端接口后：用 curl 测试一次
- [ ] 改前端页面后：列出受影响的所有页面
- [ ] 改数据库模型后：检查种子数据和已有数据兼容性

## 违规后果

如果自查不通过，**先修再 commit**，不要带着已知问题提交。
